** TODO performance — one request per metarecord
The recurring defect of this project, in its HTTP form.

*** TODO =mf order= writes one revision per child
Measured with a counting stub: N children cost N+1 =PUT=s, so N transactions,
N fsyncs, and — the part that matters — *N revisions of the log*, where every
other bulk operation in the project is one revision (see the =write_matches=
scaffold in =routes.rs=). Undoing a numbering therefore takes N rollbacks.

Blocked on a decision: the set layer applies the *same* value to a whole set,
while each child here gets its own position. It needs an endpoint taking
=(uuid, value)= pairs — purely additive, so no =API_VERSION= bump.

The bulk pass took the linking phase from 6 reads per scope record to 1. The one
left is =record_at_path=, which asks for the occupant of a position on the
*other* side — keyed by a path, not by a uuid, and no set endpoint answers that.

*** TODO no DSL spelling for a list of UUIDs: =uuid_in [a, b, c]=
The IR has =UuidIn { uuids }= and the DSL reaches it only one UUID at a time,
through the bare UUID atom. A set therefore has to be spelled as an =OR= of N
atoms — N predicate nodes for what the IR holds as one list, which is the shape
§8 names as the compound-select limit.

A bracketed list atom, =uuid_in [3f2a…9b, 7c11…04]=, compiles to the existing
=UuidIn= node directly. Purely additive to the grammar (=uuid_in= would join
=osm=/=osmd=/=same= as a word recognised only in operator position, so a field
named =uuid_in= stays usable), no =API_VERSION= bump — the wire format already
carries the list. Same accepted spelling as the atom: bare 32-hex, comma
separated.

Wanted by every shell client that holds a set of uuids and wants to say "these
ones": today it either loops or builds an N-term =OR=.

*** TODO the CLI cannot read a scope by batches: no =--cursor=, no =--count=
The daemon already pages: =POST /query= takes =limit= + an opaque keyset
=cursor=, answers =next_cursor=, and returns the full =total= on =count: true=
(O(1) through the bitmap index). *None of it reaches the shell.* =mf metarecord
get --limit N= caps the *total* and loops over the pages internally
(=commands.rs=, the =next_cursor= loop), so there is no way to say "the next 100
after those" — a shell client either takes everything or takes a prefix.

That is why the shipped tagging scripts hold their whole scope in memory behind
=MF_GUI_MAX_ENTRIES= (=docs/review-followups.md= §12): a bound, not a fix.

Feasible and cheap — it is *exposure*, not new machinery: print =next_cursor=
(stderr, or a =--tsv= column), accept =--cursor <token>=, add =--count=.
Performance is unaffected: keyset pagination is index-backed and stable under
concurrent writes (unlike an offset), which is precisely why the cursor is what
should be exposed rather than a =--offset=.

Two caveats to spell out in the spec when it is done: a cursor is bound to a
hash of (query, sort) and is rejected by any other request shape, and a record
edited between two pages moves with its sort key like any keyset paging.

** TODO =POST /repos/:repo/query/explain=: what will this query cost, before running it
Specified in [[file:docs/spec-query-cost.org][docs/spec-query-cost.org]] — not implemented. A client decides (drop a
per-question counter, warn, refuse) instead of the daemon refusing query shapes:
the set of shapes the bitmap index declines is an implementation detail that must
keep moving, so it must not become user-visible surface. The spec covers the
symbolic cost model (built during compilation, one implementation shared with
=index::eval=), the parameter/cost tables, the calibration constants, and the
separation between the query's intrinsic cost and the moment's state.

** TODO correctness, minor
*** TODO =daemon/src/sync.rs= =locate()= uses =Path::exists()=
It follows symlinks, like the seven sites fixed in "a broken symlink is a file
that is there". Harmless here — it probes the sync database file that metafolder
creates itself under =internal/=, never a tracked path — which is why it was left
alone and excluded from the =mf-path-exists-follows-symlinks= semgrep rule's
scope. Worth revisiting only if that file ever becomes user-placeable.

*** TODO =compute_watched_dirs= swallows an unreadable directory entry
It mirrors =reconcile::walk=, but the walk propagates a failed =DirEntry=
(=entry?=) while the watcher's version drops it (=entries.flatten()=). The two
therefore disagree about a directory whose entry cannot be read: the reconcile
aborts, the watcher silently skips. Decide which is right and make both do it.

*** TODO the GUI orphan fix has no integration test
=fs_exists= (the entry itself, links included) is unit-tested in Rust and the
wiring is enforced by =tsc=, but no test mounts =metarecord-list= with a broken
symlink and checks the row is not coloured as an orphan. The harness exists —
=frontend/tests/metarecord-list-live-update.test.ts= already models "which paths
are on disk" and now routes =fs_exists=.
