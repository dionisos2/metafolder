#+TITLE: Roadmap

What is left to do, most urgent first. Done work is not kept here: it is in
the git history and the CHANGELOG. Deferred work is a wiki note with
=status: deferred= or =proposed= (=scripts/doc ls --status deferred=; doc
"Version scope and non-goals"); the ones worth keeping in view are listed at
the end.

* TODO performance
The recurring defect of this project is a cost that grows with the repository
where it should grow with the answer. Each item names where.

** TODO =FollowsTransitive= materialises the whole subtree
One descendant bitmap per root, read whole where only the page is wanted.
Only an unsorted query could stop early: a sort needs the full candidate set.
Measured 28 September 2026 (=query.folder=, a page of 100 under a folder
holding the whole repository, L = 105 000 nodes): +0.4 ms over =query.page=,
about 4 ms extrapolated to a million. Small; one of the planner's choices
(below) rather than an item of its own: a per-candidate ancestry check with an
early stop, for an unsorted page under a large subtree.

** TODO unanchored =:path= patterns walk the whole stored forest
=aff0be6= made a =:path= comparison and a pattern anchored on a literal prefix
seek their paths on KV (=PathSeek=, 64 648 → 6 key reads for an exact path).
A pattern with no anchor (=mfr_path:path ~ "mp3$"=) still walks every node.
The =osm= path's way out applies in part: a pattern ending with =$= and no =/=
in its last literal can only match on the last name, so the trigrams of that
literal give the candidates, verified on their assembled paths. Low priority:
the GUI's finder builds =osm= queries, not these.

** TODO the query planner: the next choices
Built September 2026 from the cases profiling found, not from the old design
(the old adaptive planner stays a record: doc "Indexing architecture"): a deferred text leaf's
candidates narrowed by trigrams (=495ea1b=), and the first choice made on a
cost — an =osm= path's anchors cut by a rare earlier term (=1140e07=). What
is left, each to measure before building:
- the page under a large subtree (above);
- a two-term =osm= path whose earlier term is common: the bench's finder,
  still ≈ 5 ms on L, nearly all of it each anchor's ancestry (≈ 2 µs a random
  read). No bitmap formulation found cheaper on that shape;
- whatever the slow log shows next on a real repository: reads are logged per
  phase, a read is logged from 100 ms or 100 000 keys, and =mf slow replay=
  runs a logged query again for its phases now (doc "Slow log").

** TODO =mf order= writes one revision per child
N children cost N =PUT=s: N transactions, N fsyncs and N revisions, so undoing
a numbering takes N undos. The read side is bulk already; the write loop is
=core/src/order.rs= (=client.put= per planned position). Blocked on a
decision: the set layer applies the *same* value to a whole set, and each
child here gets its own — it needs an endpoint taking =(uuid, value)= pairs
(additive, no =API_VERSION= bump).

** TODO =mf sync plan=: the target-side position lookup is per record
=record_at_path= (=core/src/sync/plan.rs=, also used by =run.rs=) asks for the
occupant of one position on the other side, once per identity position. The
mechanism for a set is there: an =Or= of =field:path = "…"= equalities is
resolved by the forest into one =uuid_in= set (and on KV each one is now a
seek, not a walk), and =query/fields/resolve-tree= maps the answers back to
their paths. What is left is rewriting the caller.

* TODO query API
** TODO no native =In { field, values }=
"This field is one of these N values" is still an =Or= of N =Eq=: about 2N
nodes, against the caps of =query_validate.rs= (=MAX_QUERY_NODES= 2000,
=MAX_COMBINATOR_OPERANDS= 200 — kept as guards against a malformed query,
decided September 2026). A native =In= is one node and makes the caps painless
for membership. Uuids are done already: =uuid_in=, and the DSL folds an =Or= of
bare uuids into one.

** TODO the CLI cannot read a scope by batches: no =--cursor=
The daemon pages (=POST /query=: =limit=, an opaque keyset =cursor=,
=next_cursor=), and =mf metarecord get --count= exists, but =--limit N= caps the
total and pages internally: a shell client takes everything or a prefix. What
is left is exposure: print =next_cursor= and accept =--cursor <token>=. To
write down in the spec with it: a cursor is bound to a hash of (query, sort),
and a record edited between two pages moves with its sort key.

** TODO fanotify: what the note leaves open
From doc "Watcher open questions" (and doc "The fanotify broker"):
- events of the covered filesystems outside the roots are dropped by the
  broker, but still queued and read: a flood of them can overflow the group's
  queue for everyone. Ignore marks (=FAN_MARK_IGNORE=, 6.0+) on the busiest
  outside directories would stop them in the kernel;
- a mark whose filesystem left the root but is still mounted elsewhere stays
  until the broker restarts (costs work, not correctness);
- network filesystems: a per-repository override of the source, not asked
  for so far.

* TODO correctness, minor
** TODO a rollback can bring back a node at several positions
Navigation puts rows back without going through the Writer's checks (as it does
for a detached node, see =index_oracle.rs= =tree_ref_sort_with_a_detached_node=),
so rolling back to a state written before =4ffe261= can restore a metarecord
at two positions. =mf repo check= names it afterwards. Refuse it, or accept and
document it — to decide.

** TODO =compute_watched_dirs= swallows an unreadable directory entry
It mirrors =reconcile::walk=, but the walk propagates a failed =DirEntry=
(=entry?=, =reconcile.rs=) while the watcher's version drops it
(=entries.flatten()=, =watcher/inotify.rs=). The reconcile aborts where the
watcher silently skips. Decide which is right and make both do it.

** TODO the GUI orphan colouring has no test on a broken symlink
=fs_exists= (the entry itself, links included) is unit-tested in Rust, but no
frontend test mounts =metarecord-list= with a broken symlink and checks the
row is not coloured as an orphan. The harness is there
(=metarecord-list-live-update.test.ts= models the files on disk and routes
=fs_exists=).

** TODO =daemon/src/sync.rs= =locate()= uses =Path::exists()=
It follows symlinks. Harmless — it probes the sync database file metafolder
creates under =internal/=, never a tracked path, which is why the
=mf-path-exists-follows-symlinks= semgrep rule leaves it out. Revisit only if
that file ever becomes user-placeable.

** TODO tags still in the old format
The tag model moved to singular names and a =path= TreeRef (=tag=,
=negative_tag=, =mixed_tag=). Tags written before (refs =tags= /
=negative_tags=, the hierarchy in a string =name=) are invisible to =mf tag=.
No conversion was shipped, because it is not known whether any such data
exists: check, and write the conversion if it does.

* TODO structure
Not problems of behaviour; worth doing for navigability, each a large diff.
- The big panels are one =mount()= each (=metarecord-list= 1 895 lines,
  =metarecord-detail= 2 203): they share the instance's state, so extracting
  anything means passing an explicit context — a rewrite, not to start
  casually.
- Long sequential functions (=reconcile_full_reported= 326 lines,
  =flush_pending_once= 243): linear phase sequences over shared state;
  extraction would cost ten-parameter signatures. Left alone deliberately.

* TODO shipped tagging scripts
** TODO the mock =mf= log loses argument boundaries
=scripts/lib/mf-mock.sh= (and =daemon-fixture.sh=) log each call as ="$*"=,
arguments joined by spaces, so an assertion glob can match text *inside* an
argument — a DSL query holds spaces. No false positive seen, and the log's
form is the interface of =mock_count= / =mock_calls_matching=: changing it
rewrites the hundred assertions of six suites. Deferred, cost above gain. If it
ever bites: keep =$*= as the readable log and write a second one, arguments
separated by =\x1f=, with a =mock_count_argv= for the assertions that need it.

** TODO =mf path= once per question in the tagging scripts
=gui-tag-folder.sh= and =gui-tag-pair.sh= call =mf path "$uuid"= for the preview
at each question, right after reading the same record's *relative* path
(=--resolve-tree mfr_path=). Only the repository's absolute root is missing to
build it without the round-trip. One HTTP call per keystroke of a human: not
felt. Clean fix: a CLI printing a repository's root (=mf repo root=, or a
=--root= on =mf repo list=, whose JSON would need =jq=), read once per run —
a CLI addition to weigh first.
