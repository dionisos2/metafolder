#+TITLE: Roadmap

What is left to do, most urgent first. Done work is not kept here: it is in
the git history and the CHANGELOG. Deferred work is a wiki note with
=status: deferred= or =proposed= (=scripts/dev/doc ls --status deferred=; doc
"Version scope and non-goals").

* To discuss
Every deferred or proposed note, to be gone through one by one: build it, keep
it deferred, or drop it.

** Unknown occupant of a sync destination
Agreed with the user (10 November 2026): a copy or a move whose destination
holds an entry the run does not know — not the old version of the linked
file, as its record's stamp says — is not started: the operation is skipped
as impossible and the link left uncommitted. A known old version still goes
to the trash. Today =place_content= and =relocate= trash any occupant.

** Rework the linking phase
The linking phase is to be discussed again as a whole (user, 10 November
2026). It takes over two points of doc "Sync open questions": records without
a position (exact twin only), and a file moved before its first sync (synced
as a new file).

** Content hashes kept fresh
Accepted direction (user, 10 November 2026), design to settle: a command to
compute =mfr_full_hash= for a set of files; a way to mark files whose hash is
kept fresh, the watcher recomputing it on =Modify= instead of dropping it and
reconcile computing it when absent; sync comparing the two sides' hashes when
both hold a fresh one (snapshot keeping each side's), which also spares the
byte comparison. Open: how a file is marked (=mfr_*= is reserved); a stored
hash is trusted on its mtime and size, so without the watcher the same-second
rewrite stays unseen.

** Configuration open questions
doc "Configuration open questions": installing without a source checkout, a
sync racing an editor, leaving a conflicted merge to your own git tools.

** Duplicate open questions
doc "Duplicate open questions": duplicate directories, near-duplicates,
keeping a decision on a group across scans.

** Schema open questions
doc "Schema open questions": sharing a schema between synced repositories,
full validation at creation, range constraints.

** Watcher open questions
doc "Watcher open questions": a per-repository choice of source.

** Platform open questions
doc "Platform open questions": Unicode normalisation of names, Windows long
paths, what a port to macOS or Windows would take.
