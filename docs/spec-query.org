* Simplified query language

The normal DSL (doc "Query DSL grammar") is precise but verbose for everyday filtering
(=genre = "jazz"=, =AND=, =IS PRESENT=…). The /simplified query language/ is an
ergonomic surface that **transpiles to normal DSL text**, which is then parsed
by =parse_query= as usual. Its entire syntax is defined by a grammar the user
can edit — nothing is hard-coded; the shipped conveniences are default grammar
rules, not built-ins.

** Pipeline

#+BEGIN_SRC
simplified text → [ lexer → grammar engine ] → normal DSL text → parse_query → Query IR
#+END_SRC

The grammar engine lives in the =core= crate: a small hand-written
recursive-descent / PEG-style interpreter with output templates (no external
parser library — runtime-loadable grammars are rare and the template layer is
ours regardless). It emits normal DSL *text*; the existing =parse_query= turns
that text into the =Query= IR. The two stages have distinct error surfaces: a
/grammar error/ (the simplified input does not parse under the grammar) is
separate from a /DSL error/ (the produced text is rejected by =parse_query=).

The simplified language is **not** a superset of the normal DSL: a grammar may
accept neither, either, or a mix. Expansion is therefore **not idempotent** on
normal-DSL input. Consumers keep the two explicit — the GUI editor shows both
(see [[file:spec-gui.org][spec-gui.org]], =metarecord-list= panel), and the CLI gates simplified
input behind =mf query --simplified=.

** Configuration

The grammar is a single file in the shared (core) config directory,
=~/.config/metafolder/core/query-grammar=, installed by
=metafolder-sync-config= (see doc "Configuration"). It is
**global** (not per-repo) and read by each client (GUI/CLI) for client-side
expansion — the daemon never reads it. An empty file = no rules = the
simplified language accepts nothing. A *missing* or *malformed* grammar is an
error when a client loads it (no fall back to an embedded default); the normal
DSL needs no grammar and is unaffected.

** Lexer (fixed)

A fixed tokenizer (not user-configurable) turns the input into a token stream,
discarding whitespace between tokens:

| Token     | Matches                                                                   |
|-----------+---------------------------------------------------------------------------|
| =WORD=    | =[A-Za-z_][A-Za-z0-9_]*=                                                   |
| =NUMBER=  | integer or float literal                                                  |
| =STRING=  | a double-quoted literal ='"' … '"'= (with escapes)                        |
| =SYMBOL=  | a maximal run of punctuation characters (=:=, =~=, =>=, =>==, =..=, =+=, …) |
| =UUID=    | exactly 32 ASCII hex characters — a metarecord UUID                        |
| =(= =)=   | grouping, each its own token                                              |

Whitespace is insignificant except as a token separator: =genre=jazz= and
=genre = jazz= tokenize identically, and so do =100MB= and =100 MB=. Maximal
munch on =WORD= gives free word boundaries — a literal ="tag"= in the grammar
never matches the token =tags=.

=UUID= is matched *before* =NUMBER= and =WORD=, since a UUID may start with
either a digit or a letter and would otherwise be split in two. The run must be
maximal on both sides — 33 hex characters are not a =NUMBER= followed by a
=UUID=, and =<32 hex>_x= is one =WORD=. A run that is not exactly 32 long is
left to =NUMBER=/=WORD= as before: the fixed tokenizer reports nothing, the
grammar decides (unlike the normal DSL's lexer, which can name a truncated
UUID because it knows a bare hex run has only one possible meaning there).

** Grammar notation

A grammar is a list of named productions; the start production is =query=.

| Form                  | Meaning                                                                       |
|-----------------------+-------------------------------------------------------------------------------|
| =name = ...=          | production definition                                                         |
| =a b=                 | sequence                                                                      |
| =a \vert{} b=         | ordered choice — first alternative that succeeds wins, no backtracking afterwards |
| =a*= =a+= =a?=        | repetition: zero+, one+, optional (adjacent)                                  |
| =a ** s= =a ++ s=     | repetition separated by =s=: zero+, one+                                      |
| =( ... )=             | grouping                                                                       |
| ="lit"=               | matches one token whose text equals =lit=                                     |
| =WORD= =NUMBER= =STRING= =UUID= | matches a token of that class                                       |
| =label:item=          | binds =item='s match to =label= (a single value, or the list for a repetition) |
| =item => template=    | the production's output template                                              |

A production **without** =>= returns the raw source text it matched (so =STRING=
keeps its quotes and =WORD= stays bare).

** Template language

Right of =>=, a template is literal text with two kinds of holes:

- =$name= — interpolate the capture =name= (its text) verbatim.
- ={ expr }= — evaluate =expr= and interpolate the result.

The base type is **text**; every capture is text. There is **no implicit
coercion** — converting text to a number is explicit, which keeps text fidelity
(e.g. ="007"= stays ="007"=) and leaves room for future text/date functions.
Inside ={ }=:

| Construct           | Notes                                                                            |
|---------------------+----------------------------------------------------------------------------------|
| =$name=             | the capture's text                                                               |
| =+ - * / %=         | arithmetic — operands must be numbers                                            |
| =num(x)=            | parse text =x= as a number (error if not numeric)                               |
| =str(x)=            | render =x= as a DSL string literal — idempotent quoting (quote a bare word, leave an already-quoted string) |
| =join(sep, list)=   | join a repetition's captured list with =sep=                                     |
| =now()=             | current time as Unix milliseconds (a number); makes relative-date rules time-dependent, hence expansion of those rules is not reproducible across calls |

Arithmetic is integer unless an operand is a float; the result is reformatted to
text. Text concatenation needs no ={ }= — adjacent literals and =$captures= in
the template already concatenate. The v1 set above is intentionally minimal;
more functions are localized engine additions that do not break existing
grammars (no migration; pre-v0.2).

** Default grammar

Installed and fully editable. Comparison operators mirror the normal DSL (=,
!=, <, <=, >, >=); =field = value= routes by token class so typed values keep
their DSL type (=rating=4= → =rating = 4=, not ="4"=; =seen=true= → =seen = true=).
Conjunction is juxtaposition or the explicit =AND= keyword (=a b= ≡ =a AND b=):

#+BEGIN_SRC
query = q:or                       => $q
or    = items:and ++ ("OR" | "+")  => {join(" OR ", $items)}
and   = items:andterm +            => {join(" AND ", $items)}    # juxtaposition or AND
andterm = "AND" u:unary            => $u
        | u:unary                  => $u
unary = "!" u:unary                => NOT $u
      | a:atom                     => $a
atom  = "(" q:query ")"            => ($q)
      | p:predicate                => $p

# the part edited most of the time: the predicate alternatives
predicate =
    f:field "="  v:STRING   => $f = $v
  | f:field "="  n:NUMBER   => $f = $n
  | f:field "="  "true"     => $f = true
  | f:field "="  "false"    => $f = false
  | f:field "="  w:WORD     => $f = {str($w)}
  | f:field "!=" v:STRING   => $f != $v
  | f:field "!=" n:NUMBER   => $f != $n
  | f:field "!=" "true"     => $f != true
  | f:field "!=" "false"    => $f != false
  | f:field "!=" w:WORD     => $f != {str($w)}
  | f:field "~"  v:value    => $f MATCHES {str($v)}
  | f:field "osm"  v:value  => osm($f, {str($v)})
  | f:field "osmd" v:value  => osmd($f, {str($v)})
  | f:field ">=" n:number   => $f >= $n
  | f:field "<=" n:number   => $f <= $n
  | f:field ">"  n:number   => $f > $n
  | f:field "<"  n:number   => $f < $n
  | f:field "?"             => $f IS PRESENT
  | "under" v:value         => mfr_path ->* {str($v)}
  # date macros — see below
  | df:datefield "younger" d:duration            => $df > @{now() - num($d)}
  | df:datefield "older"   d:duration            => $df < @{now() - num($d)}
  | df:datefield "since"   v:value               => $df >= @{str($v)}
  | df:datefield "before"  v:value               => $df < @{str($v)}
  | df:datefield "between" a:value "and" b:value => $df >= @{str($a)} AND $df <= @{str($b)}
  | "##=" v:tagpath         => tag -> (mf_schema = "tag" AND path = {str($v)})    # exact node, full path
  | "#="  v:tagpath         => tag -> (mf_schema = "tag" AND path =>* {str($v)})  # subtree, full path
  | "#"   v:tagosm          => tag -> (mf_schema = "tag" AND osm(path, {str($v)})) # fuzzy: osm over the path
  | u:UUID                  => $u                # a pasted UUID: that one metarecord
  | f:field "->" u:UUID     => $f -> ($u)        # the records pointing at it
  | "fav"                   => rating >= 4

# field aliases: map a few names, pass the rest through. `p` = the file path;
# `path` is left free so it reads as the tag hierarchy field.
# Note: WORD excludes ":", so this production carries no ASPECT — the simplified
# language cannot spell `p:value`, and a query needing one is written in the
# normal DSL (or the grammar is extended locally, which is what it is for).
field  = "p"    => mfr_path
       | "size" => mfr_size
       | w:WORD => $w
value  = STRING | WORD
# tag path values: `tagpath` keeps slashes (a real path), `tagosm` turns them
# into osm term separators; a quoted string passes through verbatim.
tagpath = v:STRING       => $v
        | ps:WORD ++ "/" => {join("/", $ps)}
tagosm  = v:STRING       => $v
        | ps:WORD ++ "/" => {join(" ", $ps)}
number = n:NUMBER "MB"   => {num($n) * 1048576}
       | n:NUMBER "mins" => {num($n) * 60}
       | n:NUMBER        => $n

# date fields and durations (durations are milliseconds)
datefield = "modified" => mfr_mtime
          | "created"  => mfr_btime
duration  = n:NUMBER u:dur_unit => {num($n) * num($u)}
dur_unit  = ("s" | "sec" | "secs" | "second" | "seconds") => 1000
          | ("min" | "mins" | "minute" | "minutes")       => 60000
          | ("h" | "hr" | "hrs" | "hour" | "hours")        => 3600000
          | ("d" | "day" | "days")                         => 86400000
          | ("w" | "week" | "weeks")                       => 604800000
#+END_SRC

Ordering matters under ordered choice: the operator forms (=,= =!=,= =~=, =?=…)
precede the bare-word alias (=fav=). The tag macros come in two families. Bare
=#X= is the *fuzzy finder*: ordered-substring matching (=osm=) over the tag
path, so you can name a leaf without its ancestors (=#jazz= finds
=musique/jazz=); a =/= is an osm term separator, not a path anchor
(=#a/b= → =osm(path, "a b")=, matching =a= then =b= in order but not
necessarily contiguous or root-anchored). A quoted value is one contiguous
term (=#"jeux video"=). =#=P= and =##=P= *anchor the full path* from the root —
=#=P= its subtree (=path =>* "P"=), =##=P= that exact node (=path = "P"=) — and
accept an unquoted slash-path (=#=musique/jazz=). The four sigils =#=, =#==,
=##=  are distinct tokens under maximal munch, so their order is immaterial. To
negate, keep a space (=! #musique=) — a bare =!#= lexes as one symbol token.
The file-path field is aliased to the terse =p= (=p osm "sci fi"=, =p ?=),
leaving the word =path= to pass through as the tag hierarchy field name.

A *pasted UUID* passes straight through: the =UUID= token class carries it to
the normal DSL's own UUID atom (see doc "Query DSL grammar"), so the identifier the GUI
copies works in the simplified box too — one form in both languages, no sigil.
=tag->UUID= (or any ref field) selects the records pointing *at* it, the
=Follows= form the tag macros above build by path. No other rule can start with
a =UUID= token, so its position among the alternatives is immaterial. Several
pasted uuids need no list form here: the boolean skeleton's =+= already joins
them (=3f2a…9b + 7c11…04=), and the normal DSL folds the =OR= it expands to into
one =uuid_in= node.

The date macros read as English: =modified younger 3d= (modified within the last
three days) → =mfr_mtime > @<now − 3 days>=; =created older 2 weeks= →
=mfr_btime < @<now − 2 weeks>=; =created since "2024-01-01"= → =mfr_btime >= @"2024-01-01"=;
=modified between "2024-01-01" and "2024-06-01"= →
=mfr_mtime >= @"2024-01-01" AND mfr_mtime <= @"2024-06-01"=. Durations accept the
unit words above and their abbreviations, with or without a space (=30min=, =3d=,
=2 weeks=); absolute dates are quoted ISO-8601. =modified= maps to =mfr_mtime= and
=created= to =mfr_btime=; edit the grammar to target other datetime fields.

** Validation

At load the grammar is checked: every referenced production exists, the start
production =query= is present, **left recursion is rejected** (=or = or ...=
would loop forever) with an error naming the offending production, and every
string literal must tokenize to **exactly one token** under the fixed lexer.
A literal matches one input token by text, so one that lexes to several tokens
(e.g. =\"/fav\"= → =/= , =fav=) or to none (whitespace-only) could never match;
it is rejected with an error naming the pieces and suggesting the split form
(=\"/\" \"fav\"=). Grammar and expansion errors carry the position in the
simplified input.

** Dates

Relative and absolute date filters are supported, on three layers:

1. =datetime= values are stored as Unix milliseconds and compared numerically
   (see [[file:spec-data-model.org][spec-data-model.org]]).
2. The normal DSL has a *datetime literal* =@"<iso>"= / =@<ms>= (see
   the DSL grammar (doc "Query DSL grammar")), so =mfr_mtime > @"2024-01-01"= compiles to a real
   =datetime= comparison.
3. The template language exposes =now()= (current Unix ms), and the default
   grammar ships the =modified=/=created= date macros (=younger=/=older=/=since=/
   =before=/=between=, see [[*Default grammar]]). Relative forms expand to
   =@{now() − duration}=.

Because =now()= is read at expansion time, expanding a relative-date macro is
time-dependent (not reproducible across calls). Calendar-aware durations
(months, years) are intentionally left out; the supplied units run from seconds
to weeks. Richer relative grammars are a matter of editing the grammar file.

** Where expansion runs

Expansion is a **pure, client-side transformation**: it depends only on the
grammar file and the input text, never on the daemon or any repository. The
GUI and CLI link =metafolder-core= and call the shared engine directly
(`core::simplified::engine::expand`) — there is *no* daemon endpoint for it.
The GUI loads the grammar at startup and exposes a local backend command
(=metafolder.query.expand=, see spec-gui); the CLI loads it when
=--simplified= is used. Relative-date macros (=now()=) therefore resolve
against the **client's** local clock.

A grammar/expansion error is reported by the client (the GUI shows it under
the simplified input; a subsequent normal-DSL parse failure is a separate
error shown under the normal-DSL input).
