Queries

Most panels that list metarecords are driven by a query — a filter that selects which metarecords appear. There are two languages:

  • the simplified query you usually type (short, forgiving, configurable), and
  • the normal DSL it expands into — precise but more verbose. This page documents the DSL.

In the metarecord list the query box accepts simplified text; Show normal DSL reveals the expansion, which you can freeze to edit as DSL by hand. Focus the box with Ctrl+/. An empty query matches everything.

Boolean structure

Combine predicates with AND, OR and NOT, grouping with parentheses. NOT binds tighter than AND, which binds tighter than OR. Keywords are case-sensitive uppercase (the boolean literals true/false are lowercase). 

rating > 3 AND genre = "jazz"
NOT (seen = true OR rating IS UNKNOWN)

Comparisons

field op literal with = != < <= > >=. A literal is an integer, a float, a "quoted string", true/false, or a datetime.

  • A datetime literal is @ then a quoted ISO-8601 string (@"2024-01-01", @"2024-01-01 12:30:00", UTC) or bare Unix milliseconds (@1704067200000). Use it to compare against datetime fields: mfr_mtime > @"2024-01-01" (a plain string would not compare as a date).

Three-valued presence

A field can be present, explicitly empty, or never set — three distinct states:

field IS PRESENThas a value that is not Nothing
field IS ABSENTset to Nothing — an explicit "does not apply"
field IS UNKNOWNthe field was never set on this metarecord

For example a deleted file's metarecord has mfr_path IS ABSENT (the path was blanked), not UNKNOWN.

Regex — MATCHES

field MATCHES "regex" is a case-insensitive regular-expression test on the field's text. On a TreeRef field it matches against the resolved path. 

title MATCHES "[Ll]ive"

Traversal — following references

Fields can point at other metarecords (a Ref) or form a tree (a TreeRef like mfr_path). Follow them:

field -> "path" direct TreeRef step: the field's parent node is at path
field -> (query) the referent (Ref target, or TreeRef parent) satisfies query
field ->* "path" transitive (TreeRef only): a descendant of path
field ->* (query) a descendant of any node matching query 
mfr_path ->* "/music/jazz"
author -> (name = "Coltrane")

Tags

A tag is a metarecord marked type = "tag"; its place in the tag hierarchy is a TreeRef field, path (its display label may be left unset — never rely on a name). A record carries a tag through a Ref field — tag in the default schema — pointing at that entry. So you select by tag by following the ref into the tag tree, using the very same TreeRef traversal as mfr_path — no name matching. Tag paths carry no leading / (unlike mfr_path, whose root is the empty-named filesystem root).

Records carrying one specific tag — the node jazz under music:

tag -> (path = "music/jazz")

On a TreeRef field, an = operand that contains a / is an exact-path match (the one node at that path), not a leaf-name compare — so this pins that single tag.

Records carrying that tag or any tag below it in the hierarchy use =>*, the inclusive subtree step (the node itself plus every descendant). Useful because tagging a child drops the now-redundant ancestor tag, so records may carry only the narrower tag: 

tag -> (path =>* "music/jazz")

(->* is the strict form — descendants only, excluding the node itself.)

Ordered-substring — osm / osmd

osm(field, "terms") matches when each whitespace-separated term appears in order (the finder's semantics): osm(mfr_path, "scien fic") matches …/science-fiction/…. osm follows a TreeRef path; osmd matches a field's text directly.

Examples

mfr_path IS ABSENT
mfr_type = "file" AND mfr_path -> (mfr_path = "2021")
mfr_path ->* "/music/jazz" AND title MATCHES "[Ll]ive"
tag -> (path = "music/jazz")
type = "tag" AND (osm(path, "musi jaz") OR osmd(label, "jazz"))
