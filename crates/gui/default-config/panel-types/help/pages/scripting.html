Scripts and their questions

A shell script driven by mf gui (run it with script:run) can take over a workspace, show files and ask you questions. A question appears in its own bar just above the status line, with the keys it accepts, so no status or error message can ever hide it. It belongs to the workspaces that script owns: switching tab puts it away.

Answering

Press one of the keys shown. By convention the shipped scripts pair the arrow keys with the letters, the same way everywhere: → yes, ← no, ↑ mixed, ↓ skip. You can also type answer:send <value> in the command input.

Going back

Backspace undoes the previous answer and asks that question again. It is reserved like Escape, so no script can take the key — but where Escape ends the run, this ends only the answer. Press it repeatedly to walk back question by question, to the first one.

What "back" undoes is the script's business, since only it knows what its last answer wrote. The shipped tagging walks do it through the event log: they note where the history is before each answer and return it there, so the exact field values come back — and they re-open whatever the answer had settled, so a folder you answered "yes" by mistake can be answered differently and its files are asked about again. A script that offers it shows b in the question (the typed twin of Backspace); one that does not simply asks again.

Script keys, and getting them back

While a question is up, the keys it awaits are borrowed from the GUI: they beat every panel and global shortcut, so a script offering y/n/s is never in conflict with an n binding in the panel underneath — and the panel underneath is unusable meanwhile.

The “script keys” checkbox in the question bar hands them back. Unticked, every key means again what it means in the panel; the question stays on screen (its keys struck through) and can still be answered from the command input, or by ticking the box again. script-keys:toggle (Tab) flips it. Your choice holds for the rest of the session, but every new run starts with its keys live.

Stopping a script

Escape stops the asking script outright — the run and every command it started. It always works, whatever keys the script grabbed, because no script is allowed to take it: Escape, Backspace, Tab and : are reserved, and a script asking for one of them is refused. With the script keys unticked, Escape is an ordinary GUI key again and script:stop does the same job from the command input.

Because a stopped script does not get to clean up, scripts that need to offer their own exit do it with q — the quit key of every shipped script.
