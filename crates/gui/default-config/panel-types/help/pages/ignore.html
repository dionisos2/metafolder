Ignore patterns

Not everything under a watched directory deserves a metarecord: build output, dependency trees, editor droppings. A directory's mf_ignore field holds regex patterns; a path that matches one is skipped by the watcher and by reconcile.

Presets

Patterns are grouped into named presets — rust-build, node, python, git, hidden… — living in ~/.config/metafolder/core/ignore-presets.toml. The default preset is what a new repository starts with. Four commands apply them, each completing over the installed presets:

  • ignore:list — the available presets and the patterns currently governing the target directory (read-only: look before you write).
  • ignore:add — append a preset's patterns.
  • ignore:remove — remove exactly those patterns.
  • ignore:set — replace the whole set with them.

The target is the directory you are looking at: the file manager's current directory, else the selected metarecord's directory, else the repository root. The status message always names the directory it wrote to.

From the file manager

Entries an ignore pattern excludes are shown dimmed and struck through, with the pattern and the directory it comes from in the tooltip. Right-clicking a row offers an Ignore section: ignore that path, ignore every file with its extension, or apply a preset. Both ad-hoc gestures write onto the current directory, not the row — an ignore set governs a subtree.

The one trap: sets are not merged

The nearest ancestor with at least one mf_ignore row provides the patterns; ancestors are never merged. Writing a single pattern onto a directory that has none therefore drops the whole inherited set for that subtree.

The GUI catches this: when the target only inherits its patterns, it offers to copy the inherited set here first, so your new pattern extends what applied instead of replacing it. Declining starts that directory from an empty set — which is occasionally what you want, and never what you get by accident.

What ignoring does not do

It stops future tracking; it never deletes an existing metarecord. A file already tracked keeps its metarecord (and its metadata) until you remove it yourself.
