Simplified queries

The normal DSL is precise but wordy for everyday filtering (genre = "jazz" AND rating IS PRESENT). The simplified query is a shorter, forgiving surface that transpiles to normal DSL before it is run. It is the default input of the query box in the metarecord list panel; Show normal DSL reveals what it expands to.

Boolean skeleton

Words separated by spaces mean AND. Use OR (or +) for alternatives, ! for negation, and parentheses to group. An empty query matches everything. 

genre=jazz rating>3
genre=jazz OR genre=blues
!fav

Predicates (default grammar)

These are the shipped conveniences — the part you type most:

field=valueequality; the value's type is inferred (number, true/false, else string)
field!=valueinequality
field>n >=n <n <=nnumeric comparisons
field~textregex match (MATCHES)
field osm "a b"ordered substrings over a tree path (osm); quote several terms, a single one may be bare
field osmd "a b"ordered substrings over the field's own text (osmd)
field?present
field!?absent (value is Nothing)
field??unknown (never set)
under pathanywhere below a tree path (mfr_path ->* path)
#taghas the tag or any sub-tag (the common case) — e.g. #musique also finds musique/jazz
##taghas exactly that tag

Quote a nested tag path: #"musique/jazz". To negate, keep a space — ! #musique (a bare !# reads as one symbol).

Size and field aliases

  • path → mfr_path, size → mfr_size; any other name passes through.
  • Numbers accept MB and mins suffixes: size>=100MB, length<5mins.

Date macros

modified and created select the field (mfr_mtime / mfr_btime); durations are numbers with a unit (s min h d w):

modified younger 3dchanged in the last 3 days
created older 1wcreated more than a week ago
modified since "2024-01-01"on/after a date
created before "2024-01-01"before a date
modified between "2024-01-01" and "2024-02-01"within a range

Handy shortcuts

  • #musique → tag -> (mf_schema = "tag" AND path =>* "musique"), fav → rating >= 4 (example rules — adapt them to your own repository).

Simplified is not the DSL

The simplified language is not a superset of the normal DSL: the grammar defines its entire syntax, so expansion is not idempotent on DSL text. The two are kept explicit — the GUI shows both and lets you freeze the DSL to edit it directly; the CLI gates simplified input behind mf query -s.

Editing the grammar

Nothing above is hard-coded — every convenience is a rule in a grammar file you can edit: ~/.config/metafolder/core/query-grammar.
