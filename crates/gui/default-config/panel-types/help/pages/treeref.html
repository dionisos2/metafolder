Tree reference panel

Navigates a TreeRef forest — the hierarchical references (such as mfr_path, the file tree) that organise metarecords into trees, one forest per field name. Paths are resolved by the daemon, never walked client-side.

Navigating

↑ or k / ↓ or jmove the cursor
Enter or →descend into the node
← or Backspacego up to the parent
Home / Endfirst / last node
/back to the forest roots
rrefresh
fjump to a child by name (completes over the children shown)

Which forest it shows is chosen by its field (default mfr_path); Shift+F picks another one without leaving the keyboard — the minibuffer starts empty and completes over the repository's TreeRef fields.

What points at this node?

The ref bar answers the companion question — which metarecords reference the node under the cursor. Pick the Ref field to follow back (tag by default, the common case) and the scope, and the bar shows the query it will run: 

tag -> (path = "music/jazz")      the node itself
tag -> (path =>* "music/jazz")    the node and every tag below it

l (or List what tag points at here in the right-click menu) runs it in a metarecord list opened in the other slot, with the query left visible and editable in its normal-DSL zone — so it can be narrowed further, or composed with anything else, instead of being locked into a fixed view.

llist what the Ref field points at here
stoggle the scope (exact ⇄ + descendants)
echoose the Ref field to follow back
