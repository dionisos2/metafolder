Find in panel (Ctrl+F)

Ctrl+f searches the text the focused panel is currently showing — the browser's own find, over one panel. It works in every panel type, these help pages included: the shell drives it against whatever panel is focused, so no panel has to implement anything.

Keys

Ctrl+f open the find bar (above the command input) and start typing. Pressing it again re-focuses the bar and selects what is in it, so a second press starts a new search. The text you searched for is kept when the bar closes, so Ctrl+f then Enter resumes it.
Enter / Shift+Enter next / previous match, wrapping around at both ends.
Escape close the bar and remove the highlighting.

The bar shows the position of the current match (3/17) or no match. The current match is painted differently from the others and scrolled into view — but only when it is not already comfortably visible, so the text does not jump around while you type.

What it searches

What the panel renders, exactly like a browser's find. A term broken over several lines in the source still matches, and a match can span inline markup; hidden parts of a panel are not searched, and neither is anything the panel has not loaded — the rows of a list beyond the page you are looking at, for instance.

So this is reading what is on screen, not querying the repository. To search a whole repository, use the list panel's finder (/) or its query editor — they ask the daemon, and they match records you cannot currently see.

From a script

find:in-panel <text> searches text straight away, so a script can drive it with mf gui command 'find:in-panel "…"', along with find:next, find:prev and find:close.
