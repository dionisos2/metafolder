Metarecord detail panel

Shows one metarecord — the record under the cursor in the metarecord list — with all its fields, and lets you edit them. Fields form a multi-map: several fields may share a name.

Values and types

Each value has a type: string, int, float, bool, datetime, a reference (ref) to another metarecord, a tree reference (tree_ref, e.g. mfr_path), and a few others. A value can also be Nothing — an explicit "does not apply", distinct from the field simply not existing. Reference and tree fields are filled with a value picker rather than by typing a UUID.

Following references

Clicking a reference value opens the metarecord it points at, so a chain of them is browsed like pages. Backspace or ← goes back to the record shown before — metarecord:back, and it walks back through the whole trail, including records you reached from the list.

Under a reference, a dim line names the target: the resolved path of a tree reference, the path of a tag (and of any other ref field with a completion seed), otherwise the target's name field. A tag's hierarchy lives in its path, so without it a tag value would show nothing but a UUID.

Copying the UUID

Copy UUID in the context menu puts this metarecord's identifier on the clipboard. Pasted into a query box it is a query — a bare 32-hex UUID selects that one record, and composes with the rest (<uuid> AND rating > 3, <uuid> OR <uuid>, tag -> (<uuid>) for the records pointing at it). It works in the simplified box as well as the normal-DSL one, so there is nothing to freeze before pasting.

Editing

Move between fields with ↑ or k / ↓ or j. Then:

Enteredit the field value under the cursor
a / dadd a field / delete the field under the cursor
Ctrl+ncreate a new record (an edit is saved as it is confirmed)

The command-input m family does the same from either the detail or the list panel, with completion: m s set, m a add value, m v edit value, m d remove one value, m u unset the field, m n rename, m t retype. See the keyboard shortcuts for the full family (including the m m * bulk operations that act on the list selection).

Note: mfr_* fields are daemon-managed; overwriting one needs an explicit force.
