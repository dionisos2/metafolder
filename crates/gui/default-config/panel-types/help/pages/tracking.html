Tracking files

A metarecord can describe anything, but most describe a file: it carries an mfr_path (a TreeRef into the repository tree) plus stat-derived mfr_* fields. The daemon keeps a tracked file's metarecord in sync as the file moves, changes or is deleted.

Opt-in watching

Nothing is tracked until you ask. Two fields on a directory's metarecord control it, inherited down the mfr_path tree:

  • mf_watch — true enables watching for that directory and everything below it (until a descendant overrides it). It is false at the repository root by default.
  • mf_ignore — a set of regex patterns; a matching path is skipped. The nearest ancestor that sets mf_ignore wins (patterns are not merged down the tree).

Bringing files in

  • In the file manager, select untracked files and use Add to DB — this creates their metarecords (with mf_watch = false, so they are recorded but not yet watched).
  • Set mf_watch = true on a directory metarecord to have the daemon follow it live from then on.
  • Run reconcile:run for a full pass: it walks the tree (pruned by eligibility), creates metarecords for new files, and detects moves by content fingerprint. Reconcile never blanks a stale path — only the live watcher and explicit force writes set mfr_path = Nothing.

When a watched file is deleted its metarecord is kept; only its mfr_path becomes empty (Nothing), so history and your own fields survive.

Watching switched off

While a subtree is not watched, its metadata is deliberately frozen — the daemon will not silently rewrite mfr_* fields for files it is not tracking. Re-enable mf_watch or run a reconcile to refresh them.

Background tasks

Reconcile, query warm-up and the watcher flush run as daemon tasks; their live progress appears in the task bar above the status bar (separate from the transient status messages). Loading a repository warms its caches as one such task.
